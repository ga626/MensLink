## 最小原型

先展示用户已选的“三栏资料工作台”只读切片：真实检索、固定版本阅读与复制引用；使用显式开发启动器导入合成样本。这个切片用于评审交互，不作为 V01–V06 完整体验门通过的证明。管理配对与持久任务接入后再扩展完整原型。

在合成Obsidian Vault内实现MD/TXT单文件导入预览、资料与真实任务状态、固定版本详情、独立人改区、检索/复制引用、显式Agent授权与撤销、连接诊断。未支持格式如实标注，不扫描私人库，不做独立聊天窗口、模型下载或全量同步。

界面方向已选择三栏工作台，继承 Obsidian 视觉系统；真实交互、静态呈现、动效与用户审美分别记录。原型给用户看过后固定停在评审；未收到反馈只修当前缺陷与证据，不自行扩展PDF、平台或安装。

## GitHub与执行顺序

本地与远端基线已建立，使用短分支；不设长期develop、不因单任务创建worktree。Bootstrap首推只有四个元数据文件；治理PR #1与产品源码PR #2已合并，主线包含开发工程，仍没有发布版本。后续按 [标准开发流程](../development.md) 推进。

1. 完成治理与产品源码基线，CI与main分别验证，私人报告/运行数据留本地。
2. 继续V03–V06及必要格式探针，补管理配对、人改、持久任务等最小闭环。
3. 搭建可操作最小原型，展示效果并等待用户反馈。
4. 按反馈逐项完成首发能力，再进入同一制品的正式发布流程。

GitHub是代码审查、CI和分发协作层，不保存用户Vault、账号或本机数据库。创建仓库、合并源码、发布Release与Obsidian社区上架是不同状态；当前没有正式版本或用户体验验收结论。
