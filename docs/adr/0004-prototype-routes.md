# ADR 0004：原型的管理、人改与任务路线

状态：技术路线已选择，产品集成待完成；2026-10-20。不把探针通过写成完整功能已有。

目标是在个人电脑与合成 Vault 内形成可撤销、可恢复的 MD/TXT 闭环。保留既有 Core、SQLite、CLI 和只读 MCP 方向，不增加云服务、Redis、浏览器扩展或模型依赖；不接私人资料。

方案 A 沿用同用户命名管道，独立管理通道配对；凭据使用系统加密，人工笔记与机器快照分开，任务状态和发布指针同库事务。方案 B 让插件直写数据库，或新增 HTTP 服务、独立队列与跨库发布。A 更便于同库取消仲裁、定位和回退；B 增加入口、认证和一致性负担。选择 A，插件禁止直写数据库。

## 已证实的技术条件

- 真实 Obsidian 1.14.4 插件通过 Electron Node/net 连接既有读服务，完成库/schema握手、search→fetch固定引用和错库拒绝；服务停止后识别离线，重启同库后原引用保持。不操作日用会话或共享CLI管道。
- 独立 profile 中，原生安全存储对随机合成凭据完成写入/读取、持久存储无其明文、真实应用重启后解密与删除。上游存在加密不可用时的降级分支，因此产品必须显式检查加密能力，不可用就拒绝持久配对；不能依赖方法存在或自动明文降级。没有跨 Windows 用户或攻击性安全验收结论。
- 真实 `vault.process` 探针检测生成文件已偏离基线时保留原文件、另建待合并版，独立人工笔记逐字保持。产品仍须处理缺失基线、重复更新、重命名与冲突文件名。
- 与产品相同 Microsoft.Data.Sqlite/SQLite 3.53.3 的最小任务模型完成7项检查：未确认拒领与确认幂等、取消阻止发布、取消先赢和提交先赢两种顺序、真实子进程提交前退出的回滚/恢复、提交后退出的幂等、单worker文件租约。它只验证存储与状态机条件，未接入产品真实导入。

原始探针、失败、合成库和源码摘要仅本地保存；公开仓库没有私人profile或运行数据。以上不是正式制品、安装或用户体验验收。

## 实施合同与定向检查

1. 管理管道与 MCP 读管道分离；同用户 ACL 之外还须一次性配对、有效期和尝试上限，会话绑定库与客户端。随机长期凭据服务端用 Windows 用户保护、插件端用宿主加密存储；凭据不进 Vault、命令行、日志或回执。错库、过期、撤销、重放、不可加密和服务重启分别验收。同用户 ACL 不等于对恶意同用户进程的强隔离。
2. 机器快照与人工笔记独立。更新使用宿主原子处理并比较已知生成基线；有修改就保留文件和人工内容，另存候选，由用户处理冲突。不得以缺基线为由覆盖文件。
3. 任务采用 `awaiting_confirmation → queued → running → completed`，取消为终态。预览、确认和发布前复核范围及文件身份；取得唯一worker租约后才恢复遗留running任务。任务完成、修订、分块、索引和发布指针共用事务；不得先调用既有独立Import提交后再另写完成状态。
4. 取消与发布通过同一写事务仲裁：取消先成功则不发布；提交先完成则返回已完成。完成任务重试返回同一结果；旧数据、引用与授权保持。定向检查加入真实MD/TXT变更、撤销竞争和进程中断，不仅复测状态机模型。
5. Codex真实发现、search→fetch与离线仍需原生宿主验收；官方SDK检查不替代Desktop卡片。注册前冻结准确源码/制品和配置范围，不自动修改用户配置。界面继承Obsidian宿主语法，先确认可见布局，再接入真实链路。

迁移只做可回退的加表/字段；旧库不静默重建。新写通道、任务表与插件有完整实现及定向检查后再进入产品PR。回退先停本项目服务，保留数据库、原始文件与人工内容，旧引用和只读合同继续有效；不删除私人库、不降级为无认证写入。
