# 开发与 GitHub

MensLink 采用单仓库、短分支开发：`main → codex/<topic> → PR → CI → main`，不维护长期 `develop`。单任务使用主目录；并行任务有需要才创建 worktree。

首次顺序为远端基线、治理 PR、产品 PR；首次推送不是可用产品或正式发布。当前治理基线没有安装包，产品源码与构建检查随后通过产品 PR 接入。

每个 PR 说明具体行为变化、范围、真实检查和未验项。CI 默认只读权限；必需检查实际成功后才启用分支保护。个人维护不强制自我批准，不允许强推或删除主线。未合并候选保留在工作分支，合并后回到主线验证。

公开文件与运行数据分离。不得提交或打包凭据、私人 Vault、内部数据库、原始运行证据和本机路径。忽略文件不是秘密审计；首次公开及依赖变更仍须核对历史、许可与包内容。

CI 当前执行 `python scripts/check_repository.py`；开发前只运行与改动相关的检查，不在提交钩子重复完整回归。版本、依赖和接口变化要同步合同；schema 与引用格式变化须有兼容、迁移和回退方案。

产品以技术验证、最小原型、用户评审、后续扩展和正式交付推进。原型评审前不自行扩大范围；开发构建不作为稳定安装。发布需同一制品、真实环境验证、tag/Release 和远端下载摘要，不能以 CI 绿灯代替产品验收。
